# デザイン・機能の刷新（2026-11-18）

- きっかけ：依頼者より「家の間取りのよう。デザインから機能までやり直し、施設外では位置情報などを利用して Google マップのように使えるようにしてほしい」
- 費用：0円（Expo Go で確認可能な範囲）
- 状態：Claude Code 環境での自動検証は完了。**iPhone での確認待ち**（`docs/setup/03-iphone-check.md`）

## 1. 変更内容

| 分野 | 変更前 | 変更後 |
|---|---|---|
| 地図 | 白い背景に間取り図だけを SVG で描画 | **iPhone は Apple マップ、Android は Google マップの上に屋内図を重ねる**。施設に近づくと屋内図、離れると施設のピン |
| 施設外 | なし | 現在地表示（許可制）・現在地へ移動・**住所・地名の検索**（iPhone 標準機能）・**施設や検索した場所までの経路を地図アプリで開く** |
| 屋内・屋外の切替 | なし | GPS で敷地に入る／出るを判定して自動切替（境界付近や誤差の大きいときは切り替えない） |
| サンプル施設 | 1フロア・8店舗（60m×30m） | **2フロア・40店舗**のショッピングモール（160m×70m）。メインモール・吹き抜け・フードコート・エスカレーター（上り/下り）・エレベーター・階段・トイレ・インフォメーション・駐車場 |
| 画面デザイン | 標準部品の簡易な画面 | 地図アプリ風：全画面の地図、丸い検索バー、カテゴリーの絞り込み、フロア切替、下部の情報カード、アイコン |
| 店舗情報 | 名前・カテゴリー・営業時間・説明 | ＋**営業中／営業時間外**の表示、フロア表示、カテゴリー別の一覧 |
| 経路案内 | 距離のみ | **案内文**（「1F 南口から出発 → 約47m 進む → エスカレーターで2Fへ → … → 到着」）、フロアごとの経路表示、**最寄りのトイレへの経路** |
| 検証用 | ― | 【サンプル】施設を現在地の近くへ移動する機能（屋内外の切替を自宅などで試すため） |

オフライン保存・規制情報の鮮度管理・行動データの一時保存と重複防止・同意の分離など、Phase 1A で作った仕組みはそのまま引き継いでいます（自動検証で再確認済み）。

## 2. 設計書からの変更点（承認をお願いします）

| # | 変更 | 理由 | 影響 |
|---|---|---|---|
| 1 | **地図の第一候補を MapLibre から「Apple マップ／Google マップ（react-native-maps）」に変更** | ご要望の「Google マップのような使い心地」に最も近く、Expo Go で今すぐ確認でき、費用0円のため | MapLibre は Expo Go で確認できないため、比較（判断ポイント G2）は Phase 1B に回します。屋外の背景地図は通信が必要（屋内図・検索・経路はオフライン可） |
| 2 | Android 版を公開用にビルドする段階で **Google Maps の API キー**が必要 | Google マップを表示するため | Google Cloud の請求先アカウントの登録が必要。モバイルアプリでの地図表示自体は無料とされているが、**登録前に最新の料金を確認して報告**します。iPhone（Apple マップ）は追加費用なし |
| 3 | 施設外の経路は「地図アプリを開く」方式 | アプリ内で屋外の経路を出すには有料の経路サービスや規約確認が必要なため | アプリ内での屋外経路案内は将来対応 |
| 4 | サンプル施設を2フロアに | 実際の商業施設に近い見た目・機能（フロア移動の案内）を確認するため | PoC の対象は引き続き「1施設」。データ・経路探索は最初から複数フロア対応の設計 |
| 5 | 施設データの形式に項目を追加（敷地の範囲・正面入口・住所、地図要素の種類「建物・吹き抜け・駐車場・インフォメーション」） | 屋内外の切替・地図表示のため | DB 定義の変更はなし（施設データ一式の中身のみ） |

## 4. 残課題

| # | 内容 | 対応 |
|---|---|---|
| 1 | 屋内での現在地は GPS では不正確なため、施設内の出発地は「正面入口」または地図のタップで指定 | BLE 測位（Phase 1B・3）で自動化 |
| 2 | 店舗名の表示は拡大時のみ（重なり防止）。小さい区画では名前が省略される場合がある | iPhone での見え方を確認して調整 |
| 3 | 店舗画像は未対応（カテゴリーの色とアイコンで表示） | 管理画面で画像を登録できるようにする段階（Phase 2）で対応 |
| 4 | Phase 1A 報告書の残課題（行動データ受付の回数制限など）は継続 | 変更なし |
