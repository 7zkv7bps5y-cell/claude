# iPhone での確認チェック表（Phase 1A）

`01-windows-setup.md` の手順で Expo Go にアプリを表示してから確認してください。
各項目の結果を ○ / × で記録し、× の項目はスクリーンショットを添えて Claude に送ってください。

> Phase 1A のアプリは **Expo Go で確認できる範囲**（地図・検索・経路・オフライン保存・行動データの一時保存）です。
> BLE測位・MapLibre（ネイティブ地図）は Expo Go では動かないため、Phase 1B（Apple Developer Program 登録後）に確認します。

## B. サーバー接続あり（`02-supabase-setup.md` の後）

| # | 操作 | 期待される結果 | 結果 |
|---|---|---|---|
| B1 | アプリを開く | 上部が緑色「規制情報：最新」、「地図データ：… 公開版（第1版）」 | |
| B2 | 「検証」→ 読込元 | 「端末に保存したデータ（日時）」 | |
| B3 | iPhone を**機内モード**にして、アプリを完全に終了 → 開き直す（Expo Go が開発用の通信を必要とするため、開き直しが難しい場合は B3 は省略し B4 へ） | 地図・検索・経路が使える | |
| B4 | 機内モードのまま「検証」→「今すぐ更新を確認」 | 「通信なし」または取得失敗の表示。地図は表示されたまま | |
| B5 | 機内モードのまま「時刻を進める」+30分 | 判定「注意」、地図上部が黄色で最終取得時刻と「参考案内」の文言 | |
| B6 | +7時間 | 判定「制限（経路案内：確認後に参考案内）」 | |
| B7 | 「現在」に戻す → 同意 ON →「テスト用イベントを10件追加」→「今すぐ送信」（機内モード中） | 送信待ち 10件のまま（送れない） | |
| B8 | 機内モードを解除 →「今すぐ送信」 | 送信成功、送信待ち 0件。Supabase の Table Editor → `analytics_events` に10件 | |
| B9 | もう一度「今すぐ送信」 | 「送信データなし」。`analytics_events` は10件のまま（重複しない） | |
| B10 | Supabase の SQL Editor で下の SQL を実行 →アプリの「今すぐ更新を確認」→ 西口から「ファッション・デモ」へ「ここへ行く」 | 地図に赤い破線、「通行できる経路が見つかりません」と表示 | |

B10 で使う SQL（通行止めを1件追加。確認後は2行目で削除してください）：

```sql
insert into route_rules (facility_id, kind, severity, edge_ids, note) values ('00000000-0000-4000-8000-000000000001', 'closed', 'normal', '{e011}', '【テスト】通行止め');
-- 確認後に削除： delete from route_rules where note = '【テスト】通行止め';
```

> 補足：Expo Go は開発用の仕組みのため、機内モードでの「アプリの起動」自体が制限される場合があります。
> その場合でも B4〜B7 の「起動済みのアプリが通信なしで動くか」は確認できます。
> 完全なオフライン起動の確認は、開発ビルド（Phase 1B）で行います。
